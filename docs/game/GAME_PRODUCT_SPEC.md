# OUTSCAN: Периметр — Product Spec V1

## Назначение

`game.outscan.ru` — промопродукт OUTSCAN, который за 4–6 минут показывает ценность постоянного контроля внешнего цифрового периметра.

Целевая аудитория:

- владелец сайта или бизнеса;
- разработчик;
- системный администратор;
- веб-студия / агентство.

Ключевой вывод пользователя:

> Недостаточно однажды проверить сайт. Нужно понимать, что доступно извне, что действительно важно и что изменилось после проверки.

## Формат

- браузерная мини-стратегия;
- одна вымышленная компания «Север»;
- три игровых дня;
- 6 единиц ресурса команды;
- 5 основных задач;
- максимум 1000 игровых очков;
- без жесткого таймера;
- без регистрации;
- без реального сканирования.

## Миссия «Перед запуском»

Компания готовит рекламную кампанию. Игрок управляет внешним периметром, но обязан сохранить работу магазина.

### День 1 — увидеть периметр

Известны:

- `sever.example` — магазин;
- `api.sever.example` — заказы;
- `admin.sever.example` — рабочая зона;
- `mail.sever.example` — уведомления.

После учебного discovery появляются:

- `old.sever.example` — завершенный тестовый проект;
- `preview.sever.example` — действующая площадка подрядчика.

Задача 1: старый проект.

Оптимальное действие: убрать публичный доступ, стоимость 1, затем бесплатный recheck.

Задача 2: площадка подрядчика.

Оптимальное действие: ограничить доступ участниками проекта, стоимость 1, затем recheck.

Полное отключение предупреждает заранее, что согласование материалов остановится.

### День 2 — выбрать приоритет

Сигналы:

1. Подтвержденный публичный диагностический режим API.
2. Сертификат магазина истекает к началу третьего дня.
3. Косвенный признак устаревшего компонента.
4. Дополнительное hardening-улучшение.

Игрок заранее получает сообщение: завтра появится новый промосайт, желательно оставить 1 единицу ресурса.

API:

- корректное исправление без остановки заказов: 2;
- отключить API: 1, но оформление заказов прекращается;
- отложить: 0.

Сертификат:

- организовать продление: 1;
- отложить: 0.

Косвенный сигнал:

- уточнить: 0, сигнал не подтверждается;
- обновлять без уточнения: 2, лишняя работа.

Hardening:

- выполнить: 1;
- запланировать после кампании: 0.

### День 3 — увидеть изменение

После запуска появляется `sale.sever.example`.

Статус сначала: `Новый ресурс. Еще не оценен.`

При просмотре выясняется: публичная промостраница нужна, но служебный preview остался открытым.

Решения:

- ограничить служебную часть, оставить промостраницу: 1;
- перенести запуск: 0;
- оставить как есть: 0.

Новый ресурс можно добавить в учебное наблюдение. Мониторинг не устраняет finding.

## Основной маршрут ресурса

```text
old public access        1

TOTAL                     6
```

## Scoring

| Блок                      | Максимум |
| ------------------------- | -------: |
| discovery                 |      150 |
| 5 основных задач          |      400 |
| recheck                   |      200 |
| сохранение бизнес-функций |      150 |
| change + monitoring       |      100 |
| **Итого**                 | **1000** |

Очки не начисляются за скорость, повторное нажатие, количество открытых карточек и декоративные действия.

Лучший финал требует не только score >= 900, но и:

- 5 основных задач подтверждены recheck;
- необходимые бизнес-функции работают;
- промокампания запущена;
- наблюдение включено.

## Финалы

### PERIMETER_MONITORED

Все обязательные условия выполнены.

### CONTROL_INCOMPLETE

Бизнес работает, но есть незакрытые или непроверенные задачи либо наблюдение не включено.

### LAUNCH_DELAYED

Основной магазин работает, но промозапуск перенесен из-за незавершенной подготовки или неверного управления ресурсом.

### STORE_DISRUPTED

Игрок отключил обязательный API или пропустил известный срок сертификата.

Не использовать случайный «взлом» как наказание.

## Промобонус

V1 интерфейс может предусматривать промоблок, но фактическая акция конфигурируется отдельно.

Если акция включена:

- бонус за завершение, не за высокий score;
- один бонус на организацию/кампанию;
- entitlement только через Promotions / Access Grants;
- domain verification обязателен;
- никакого ADMIN_ATTESTED;
- условия акции получаются с trusted server endpoint, а не hardcode как вечное обещание.
