# OUTSCAN audit — 2026-09-07

## Trusted Guest supervisor runtime

- Added dependency-free ResultEnvelope signing with the existing ADR-0011 domain-separated encoding. It binds current job/attempt/fence, fixed supervisor workload and ingress audience, a 60-second lifetime, payload SHA-256/size and an active key version.
- Added `runGuestScannerAttempt`: current execution/artifact authorization → frozen non-secret launch plan → bounded single-frame IPC → exact clean exit → canonical target-bound GUEST_SAFE output → signing-key lookup → authenticated ResultEnvelope.
- Job ID, authorization reference, result credential and signing key do not enter scanner launch input. Signing keys are requested only after accepted process/output state.
- One execution deadline and AbortSignal cover IPC and process completion. Invalid streams or unknown process state request TERM followed by KILL after bounded grace; errors expose stable codes only.
- Hardened scanner policy authorization to snapshot/freeze capabilities and budgets and reject sparse/hostile inputs. Approved artifact dependency data is also immutable after authorization.
- No production child-process/container adapter, secret-manager integration, queue, CAS transition, persistence, outbound scan or public Guest route was added.
- Gate A remains PASS. Gate B1 remains in progress; Gate B2 is unchanged.
