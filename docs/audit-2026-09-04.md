## Retry and redirect revalidation flow

- Every initial request, retry and followed redirect performs a new A/AAAA query pair, full-set destination-policy decision and selected-IP pin. Retry is limited to DNS operational failures, transport errors and timeouts; pin/policy/response failures are terminal.

## Guest scan idempotency decision boundary

- Added `apps/api/src/guest-idempotency` with an exact persisted-record view and pure CREATE/REPLACE_EXPIRED/REPLAY/conflict decision.
- The lookup principal is derived only as `GUEST_SESSION:<authenticated guest_session_scope>` plus the fixed scan-create operation and bounded idempotency key. Network/browser fingerprint fields are not part of the input shape.
- CREATE anchors both idempotency and result access to an exact 1800-second window. At/after expiry, REPLACE_EXPIRED creates a new anchored window; an existing revoked row does not reopen within its original window.
- Same key/scope/hash within the window deterministically derives the original result token and reports remaining seconds without extending expiry. A different hash conflicts; removed/throwing keyrings return a redacted unavailable-token failure.
- Stored metadata must have internally identical creation/idempotency/result expiry, canonical scope/hash/key shapes and valid token metadata. Request, record and nested token fields are read once into snapshots to prevent getter-based TOCTOU.
- Tests model the database unique-conflict loser by rereading the winner and applying the same REPLAY/conflict decision, but do not claim transactional persistence correctness.
- Verification: `npm --prefix apps/api test` PASS (16 files / 367 tests); `npm --prefix apps/api run lint` PASS; `npm --prefix apps/api run typecheck` PASS; `npm --prefix apps/api run build` PASS.
- PostgreSQL schema/unique constraint/transaction isolation, routes and persistence are not implemented. Gate B1 remains open.

## Guest hostile-output projection

- Added `apps/api/src/scanner-output/guest-projection.ts` to consume the future scanner adapter's GUEST_SAFE result as bounded UTF-8 JSON bytes and return only a minimized public-shaped machine projection.
- Input above the supplied limit is rejected before decoding, and the limit itself cannot exceed the 2 MiB Guest scanner-output ceiling. Fatal UTF-8, BOM, malformed/trailing JSON, duplicate keys including escaped equivalents and nesting above 32 levels fail closed.
- The closed schema caps observations/findings/coverage/warnings at 64/256/16/32. Unknown or duplicate fields and codes, malformed fingerprints, invalid confidence, evidence above 4096 bytes and execution metadata outside current GUEST_SAFE policy budgets are denied.
- Candidate findings are deduplicated by fingerprint to one potential-risk count. Their fingerprint, severity, confidence and evidence are discarded; posture/coverage expose allowlisted machine states and warnings expose only a count.
- Negative fixtures include script markup, CRLF/log text, spreadsheet formula content, a CVE, an internal endpoint and excessive/malformed structures. Tests prove this material does not survive into the projection.
- Verification: `npm --prefix apps/api test` PASS (18 files / 438 tests); `npm --prefix apps/api run lint`, `typecheck` and `build` PASS.
- Tests used local byte fixtures only. Supervisor IPC, bounded persistence and context-specific UI/export rendering remain pending; Gate B1 remains open.
