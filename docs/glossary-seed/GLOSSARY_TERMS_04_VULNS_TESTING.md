## XSS

- `slug`: `xss`
- English: Cross-Site Scripting (XSS)
- Category: `vulnerabilities`
- Aliases: `межсайтовый скриптинг`, `cross site scripting`
- Простыми словами: Уязвимость, при которой в веб-странице может выполниться нежелательный код в контексте пользователя.
- Объяснение: Обычно речь идёт о JavaScript, который попадает на страницу через недостаточно безопасную обработку данных.
- Почему это важно: XSS может привести к действиям от имени пользователя, краже данных страницы или изменению интерфейса.
- Важно: CSP может снижать последствия части XSS, но не заменяет устранение причины.
- Связанные термины: `csp`, `httponly`, `vulnerability`
- Связанные capability: `vulnerability-detection`

## SQL-инъекция

- `slug`: `sql-injection`
- English: SQL Injection (SQLi)
- Category: `vulnerabilities`
- Aliases: `sqli`, `sql injection`
- Простыми словами: Уязвимость, при которой пользовательский ввод влияет на структуру SQL-запроса к базе данных.
- Объяснение: Она возникает, когда приложение небезопасно соединяет данные пользователя с SQL-командами.
- Почему это важно: Успешная SQL-инъекция может привести к чтению, изменению или удалению данных в зависимости от прав приложения.
- Важно: Не каждое сообщение об ошибке базы данных означает подтверждённую SQL-инъекцию.
- Связанные термины: `vulnerability`, `dast`
- Связанные capability: `vulnerability-detection`

## SSRF

- `slug`: `ssrf`
- English: Server-Side Request Forgery (SSRF)
- Category: `vulnerabilities`
- Aliases: `server side request forgery`
- Простыми словами: Уязвимость, позволяющая заставить сервер выполнять сетевые запросы к адресам, выбранным атакующим.
- Объяснение: Опасность особенно высока, если сервер имеет доступ к внутренним сервисам, localhost или cloud metadata.
- Почему это важно: Для OUTSCAN SSRF критичен и как класс проверяемой уязвимости, и как риск самого scanner infrastructure.
- Важно: Scanner OUTSCAN обязан повторно проверять DNS/IP после redirect и блокировать приватные/служебные адреса.
- Связанные термины: `vulnerability`, `ip-address`
- Связанные capability: `vulnerability-detection`

## CSRF

- `slug`: `csrf`
- English: Cross-Site Request Forgery (CSRF)
- Category: `vulnerabilities`
- Aliases: `cross site request forgery`, `межсайтовая подделка запроса`
- Простыми словами: Атака, при которой браузер уже авторизованного пользователя заставляют отправить нежелательный запрос.
- Объяснение: Если приложение доверяет только наличию сессионной cookie, внешний сайт может попытаться инициировать действие от имени пользователя.
- Почему это важно: CSRF важен для действий, изменяющих состояние: настройки, платежи, права, удаление данных.
- Важно: SameSite помогает, но для критичных действий нужна полноценная серверная защита от CSRF по выбранной архитектуре.
- Связанные термины: `samesite`, `cookie`, `vulnerability`
- Связанные capability: `vulnerability-detection`

## RCE

- `slug`: `rce`
- English: Remote Code Execution (RCE)
- Category: `vulnerabilities`
- Aliases: `remote code execution`, `удалённое выполнение кода`
- Простыми словами: Уязвимость, позволяющая удалённо выполнить нежелательный код на сервере или системе.
- Объяснение: RCE часто относится к наиболее серьёзным классам последствий, потому что может дать значительный контроль над процессом или узлом.
- Почему это важно: Подтверждённая интернет-доступная RCE обычно требует высокого приоритета.
- Важно: Название RCE описывает потенциальное последствие; реальный риск зависит от условий эксплуатации и контекста.
- Связанные термины: `vulnerability`, `exploit`, `risk`
- Связанные capability: `vulnerability-detection`

## IDOR / BOLA

- `slug`: `idor-bola`
- English: Insecure Direct Object Reference / Broken Object Level Authorization (IDOR/BOLA)
- Category: `vulnerabilities`
- Aliases: `idor`, `bola`, `broken object level authorization`
- Простыми словами: Ошибка контроля доступа, при которой изменение идентификатора позволяет обратиться к чужому объекту.
- Объяснение: Приложение может проверять, что пользователь вошёл, но не проверять, имеет ли он право читать или менять конкретную запись.
- Почему это важно: Особенно важна для API и многопользовательских систем.
- Важно: Наличие последовательных ID не является уязвимостью без ошибки серверной авторизации.
- Связанные термины: `rbac`, `dast`, `vulnerability`
- Связанные capability: `vulnerability-detection`

## Path Traversal

- `slug`: `path-traversal`
- English: Path Traversal
- Category: `vulnerabilities`
- Aliases: `directory traversal`, `обход каталогов`
- Простыми словами: Уязвимость, позволяющая выйти за пределы ожидаемого пути к файлам или каталогам.
- Объяснение: Небезопасная обработка путей может позволить читать или иногда изменять файлы вне разрешённой директории.
- Почему это важно: Проблема может раскрывать конфигурации, исходный код и другие чувствительные файлы.
- Важно: Конкретные последствия зависят от прав процесса и доступной файловой системы.
- Связанные термины: `vulnerability`, `dast`
- Связанные capability: `vulnerability-detection`

## Сканирование

- `slug`: `scanning`
- English: Security Scanning
- Category: `security-testing`
- Aliases: `scan`, `security scan`
- Простыми словами: Автоматизированная проверка ресурса по заданному набору правил и сигналов.
- Объяснение: Сканирование может быть пассивным, активным, безопасным, глубоким или специализированным.
- Почему это важно: OUTSCAN использует разные scan jobs и политики в зависимости от подтверждения владения и уровня воздействия.
- Важно: Сканирование не равно полноценному ручному пентесту.
- Связанные термины: `passive-scan`, `active-scan`, `pentest`

## Пассивная проверка

- `slug`: `passive-scan`
- English: Passive Scan
- Category: `security-testing`
- Aliases: `passive scanning`, `пассивное сканирование`
- Простыми словами: Проверка, которая использует доступные данные и безопасные наблюдения без агрессивного воздействия на цель.
- Объяснение: Это может включать DNS, TLS, HTTP-метаданные и публичные источники.
- Почему это важно: Пассивный подход подходит для гостевого уровня OUTSCAN, где владение доменом ещё не подтверждено.
- Важно: Даже пассивные запросы требуют rate limits и SSRF-защиты на стороне платформы.
- Связанные термины: `scanning`, `active-scan`

## Активная проверка

- `slug`: `active-scan`
- English: Active Scan
- Category: `security-testing`
- Aliases: `active scanning`, `активное сканирование`
- Простыми словами: Проверка, которая отправляет специальные запросы, чтобы выявить конкретные проблемы или сервисы.
- Объяснение: Она может быть более точной, но создаёт больше трафика и потенциального воздействия.
- Почему это важно: OUTSCAN разрешает активные режимы только в рамках подтверждённой цели и соответствующей scan policy.
- Важно: Активная проверка чужой инфраструктуры без разрешения не должна быть доступна через публичный режим OUTSCAN.
- Связанные термины: `scanning`, `domain-verification`

## DAST

- `slug`: `dast`
- English: Dynamic Application Security Testing (DAST)
- Category: `security-testing`
- Aliases: `dynamic application security testing`
- Простыми словами: Проверка работающего приложения снаружи через реальные сетевые интерфейсы.
- Объяснение: DAST анализирует поведение веб-приложения или API без необходимости читать исходный код.
- Почему это важно: В будущем OUTSCAN может использовать DAST для более глубоких подтверждённых проверок приложений.
- Важно: DAST может быть более intrusive, поэтому режим, scope и авторизация критичны.
- Связанные термины: `active-scan`, `pentest`, `sast`

## SAST

- `slug`: `sast`
- English: Static Application Security Testing (SAST)
- Category: `security-testing`
- Aliases: `static application security testing`
- Простыми словами: Анализ исходного кода или его представления без запуска приложения как внешнего сервиса.
- Объяснение: SAST ищет потенциальные проблемы в коде и потоках данных.
- Почему это важно: Это направление полезно при будущем подключении репозиториев OUTSCAN.
- Важно: SAST может находить потенциальные проблемы, которые недостижимы в реальном runtime, поэтому результаты требуют контекста.
- Связанные термины: `sca`, `dast`, `vulnerability`

## SCA

- `slug`: `sca`
- English: Software Composition Analysis (SCA)
- Category: `security-testing`
- Aliases: `software composition analysis`
- Простыми словами: Анализ сторонних библиотек и зависимостей приложения на известные уязвимости и риски.
- Объяснение: SCA сопоставляет пакеты и версии с базами advisories/CVE и может работать вместе с SBOM.
- Почему это важно: Позже OUTSCAN сможет использовать SCA для Git и Supply Chain Security.
- Важно: Уязвимая зависимость не всегда означает достижимую эксплуатацию в конкретном приложении.
- Связанные термины: `sbom`, `cve`, `sast`

## Пентест

- `slug`: `pentest`
- English: Penetration Test (Pentest)
- Category: `security-testing`
- Aliases: `penetration testing`, `тест на проникновение`
- Простыми словами: Контролируемая проверка безопасности, имитирующая действия атакующего в согласованных границах.
- Объяснение: Пентест обычно включает ручную работу специалиста, проверку цепочек и более глубокий анализ, чем обычный автоматический scanner.
- Почему это важно: Он полезен для подтверждения сложных рисков и сценариев, которые автоматизация покрывает неполно.
- Важно: OUTSCAN не должен называть обычное автоматическое сканирование полноценным пентестом.
- Связанные термины: `dast`, `active-scan`, `vulnerability`

## MFA

- `slug`: `mfa`
- English: Multi-Factor Authentication (MFA)
- Category: `core`
- Aliases: `многофакторная аутентификация`, `2fa`
- Простыми словами: Вход, требующий более одного независимого фактора подтверждения личности.
- Объяснение: Например, пароль может дополняться одноразовым кодом или аппаратным ключом.
- Почему это важно: MFA снижает риск захвата аккаунта только из-за украденного пароля.
- Важно: Два шага одного и того же слабого типа не всегда дают полноценную многофакторность.
- Связанные термины: `rbac`

## RBAC

- `slug`: `rbac`
- English: Role-Based Access Control (RBAC)
- Category: `core`
- Aliases: `role based access control`, `ролевой доступ`
- Простыми словами: Модель прав, в которой разрешения назначаются ролям, а пользователи получают права через свои роли.
- Объяснение: В OUTSCAN клиентские Owner/Admin/Analyst/Viewer и platform-роли должны иметь минимально необходимые права.
- Почему это важно: RBAC упрощает централизованный контроль доступа, но сервер всё равно обязан проверять tenant/object ownership.
- Важно: Скрытая кнопка в интерфейсе не является RBAC; авторизация должна выполняться server-side.
- Связанные термины: `mfa`, `idor-bola`

## Ограничение частоты запросов

- `slug`: `rate-limiting`
- English: Rate Limiting
- Category: `web-security`
- Aliases: `rate limit`, `лимит запросов`
- Простыми словами: Ограничение количества операций, которые клиент может выполнить за определённое время.
- Объяснение: Rate limiting защищает API и публичный scanner от злоупотреблений, массовых запросов и части ресурсных атак.
- Почему это важно: Для OUTSCAN важны лимиты по IP, домену, организации, scan job и другим ресурсам.
- Важно: Rate limiting не заменяет авторизацию, quotas и abuse detection.
- Связанные термины: `scanning`

## Повторная проверка

- `slug`: `recheck`
- English: Recheck / Verification Scan
- Category: `security-testing`
- Aliases: `verification scan`, `повторное сканирование`
- Простыми словами: Новая проверка после исправления, которая показывает, подтверждается ли проблема снова.
- Объяснение: Назначить исправление недостаточно; OUTSCAN должен по возможности проверить результат тем же или совместимым способом.
- Почему это важно: Повторная проверка отличает заявленное исправление от технически подтверждённого результата.
- Важно: Если проблема появляется снова после статуса Fixed, finding может быть открыт повторно.
- Связанные термины: `remediation`, `finding`, `confirmed`
