## Guest cryptographic primitives

- Added `apps/api/src/guest-crypto` without third-party dependencies, routes or persistence.
- Guest-session cookie MAC follows `OUTSCAN:GUEST_SESSION_COOKIE:v1\0 || U32BE(key_version) || session_id_32_bytes` and uses HMAC-SHA-256.
- Guest-session persistence scope follows the separate `OUTSCAN:GUEST_SESSION_SCOPE:v1\0` SHA-256 domain.
- Cookie parsing requires canonical unsigned key version, canonical unpadded base64url, exact 32-byte session/MAC values and a known keyring entry; comparison is constant-time.
- Guest result-token encoding uses the normative domain, length-prefixed UTF-8 scan ID and nonce, U64BE token version and expiry, then HMAC-SHA-256.
- Result verification fails closed for expiry equality, revocation, missing retired key, malformed/oversized token and changed scan ID/version/nonce/expiry.
- Normal session/result key rotation remains valid only while the referenced retired key is present; emergency removal invalidates access.
- Fixed literal vectors cover both binary messages, cookie/token values and Guest-session scope digest.
