# Audit — 2026-09-09

## Fixed scanner process adapter

- Added `apps/api/src/supervisor/process-launcher.ts` without another dependency. One exact approved artifact identity is bound to an absolute executable/cwd and fixed bounded arguments; shell execution and environment inheritance are disabled.
- The adapter revalidates exact launch/scanner-input shapes, canonical hostname, current scanner policy and artifact/profile identity, then writes only a bounded canonical scanner-input document to stdin. Job/attempt/authorization identity, approval metadata and ResultEnvelope keys are not serialized.
- Stdout remains the existing bounded result IPC channel, stderr is ignored, and the handle supplies stable exit/signal state plus TERM/KILL. Startup/input errors are collapsed to stable launcher errors.
- Nine local process tests passed. They use only the installed Node executable, perform no DNS/outbound request and do not prove container/OS isolation or egress policy.

## Durable Guest queue telemetry

- Added a dependency-free in-process buffer over the existing twelve closed queue processor outcomes. It produces exact stable-ID batches with saturating counters and one fixed-priority alert code; unknown outcomes, unknown fields, invalid clocks/IDs and malformed store acknowledgements fail closed.
- Added separately classified PLATFORM/INTERNAL `GuestQueueTelemetryBatch` persistence in `0006_guest_queue_telemetry.sql`. The immutable schema has no GuestScan, organization, target, session/network, payload, token, scanner or provider-label column, permits exact replay, rejects conflicting identity and expires exactly 30 days after completion.
- A store failure preserves the same pending object for retry while new counters accrue in a separate buffer. The worker now schedules fixed ten-second non-overlapping flushes, passes only normalized closed outcomes to a required callback, closes queue intake before waiting for in-flight work and performs one final flush. Adapter/reporter exceptions are contained; final storage failure becomes `GUEST_WORKER_TELEMETRY_FLUSH_FAILED`.
- This is internal lifecycle evidence only: production worker deployment and approved Ops alert export remain unevidenced Gate B1 work.

## Mounted supervisor providers

- Added concrete fresh-read regular-file sources for the already validated approval and signing-key boundaries. Approval uses an exact `{schema_version:1,approval}` envelope capped at 16 KiB; signing material uses `{schema_version:1,key_version,key_base64url}` capped at 1 KiB and decodes to exactly 32 bytes.
- Added a 4 KiB startup loader for `{schema_version:1,keys:[...]}` with 1–3 unique versions and exact canonical 32-byte keys. It reuses the owner-only private-file reader and returns a new key map per load, enabling deploy/restart-keyring-before-signing staged rotation without treating one active key as the full verification set.
- Fatal UTF-8, BOM, malformed/deep JSON, duplicate/unknown fields, non-regular files, symlinks, and lstat/open identity or size drift deny. POSIX approval files reject group/world write; signing-key files require no group/world permissions.
- Local Windows targeted evidence: 19 passed, one POSIX-only permission/symlink test skipped as not applicable. Windows ACL configuration, Kubernetes-style symlink mounts and managed Vault/KMS integration remain unevidenced deployment concerns.

- Worker exceptions, malformed outcomes, invalid clocks and run-store failure collapse to closed runtime outcomes. The CLI logs only bounded status/counters. Production deployment and export to an approved Ops alert collector remain unevidenced and blocking.

## Durable Guest result-rejection evidence

- Added `0004_guest_result_rejection_events.sql` as a separate PUBLIC_GUEST/RESTRICTED record classified in ADR-0010 and `DATA_MODEL.md`. Its composite FK binds an event to one existing GuestScanAttempt/fence; the primary key makes same-reason replay idempotent and a database insert guard rejects timestamps outside the aggregate retention window.
- The append-only row contains only scan/attempt/fence identity, a closed rejection code, deterministic security classification and whole-second occurrence time. Target, payload, digest, token, scanner output and `organization_id` have no columns. GuestScan cascade preserves the fixed 24-hour aggregate deletion boundary.
- Added a strict PostgreSQL sink. Unknown fields/codes and malformed identity reject before DB acquisition; unknown attempt/fence, database ambiguity and transaction failure collapse to `GUEST_PERSISTENCE_UNAVAILABLE`.
- BullMQ processing now requires successful rejection recording before retry. Sink failure or disagreement with the committer's security flag produces `RETRY_REJECTION_SINK`; no rejected commit is silently treated as ordinary completion.
